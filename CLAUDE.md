# ABAP-разработка в песочнице клиента

Claude ведёт разработку на ABAP. Прямого доступа к SAP нет: система
клиента стоит за двумя RDP. Код передаётся через «мост через буфер
обмена» (`docs/bridge-install.md`).

## Система
- Песочница клиента (DEV/sandbox), доступ через 2 RDP.
- Версия: **ещё не известна**. Её покажет первая строка `*@@RESULT`/`*@@BUNDLE`
  (`basis=...`). Пока она не известна, пишем код, совместимый с SAP_BASIS
  7.02: без inline-объявлений, `NEW`, `VALUE`, строковых шаблонов `|...|`
  и `@` в Open SQL. Когда версия станет известна, исправить здесь и в
  `abaplint.json`.
- ECC или S/4HANA: **уточнить**.

## Правила
- Только объекты `Z*`/`Y*` в согласованном пакете. Стандарт SAP не
  модифицировать; расширения (BAdI, enhancement) — только по согласованию.
- Никогда не просить реальные данные из таблиц: персональные, финансовые,
  клиентские. Достаточно структуры (`ZCLAUDE_EXPORT`, `S_TABL`) и
  обезличенных примеров.
- Транспорты выпускает только пользователь.
- Перед написанием кода по задаче: изучить существующие объекты через
  `ZCLAUDE_EXPORT`, предложить дизайн, согласовать.
- Код отдавать пакетом в формате `docs/bundle-format.md`, одним блоком.
  Каждый include с `MAIN=`. Перед отдачей прогнать abaplint.
- Стиль: Clean ABAP в пределах версии. Логика — в локальных классах, а
  не в FORM. Тестируемая логика покрывается ABAP Unit
  (`FOR TESTING` в отдельном include).

## Структура
- `src/bridge/` — программы моста (`ZCLAUDE_IMPORT`, `ZCLAUDE_EXPORT`).
- `src/<задача>/` — исходники по задачам; это зеркало того, что лежит в системе.
- `tasks/` — постановки задач (шаблон `tasks/TEMPLATE.md`).
- `docs/project/` — документация проекта клиента.

## Проверка
```
npx @abaplint/cli abaplint.json
```
