# Установка и использование моста через буфер обмена

Мост — две Z-программы в песочнице клиента. Через них код ходит между
Claude и SAP одним копированием в каждую сторону, без ручной вставки
по объектам.

| Программа | Что делает | Меняет систему? |
|---|---|---|
| `ZCLAUDE_EXPORT` | выгружает исходники и описания словаря в буфер обмена | нет, только чтение |
| `ZCLAUDE_IMPORT` | берёт пакет из буфера, сохраняет программы, проверяет синтаксис и кладёт отчёт в буфер | да |

## 0. Перед установкой

- Убедитесь, что правила клиента разрешают передавать код внешнему
  AI-сервису. Данные из таблиц мне не нужны: я работаю только с кодом и ТЗ.
- Проверьте буфер обмена через оба RDP: скопируйте текст на своём ПК и
  вставьте его в SAP GUI на втором сервере.
- Прочитайте код обеих программ (`src/bridge/`). Они небольшие и не
  обращаются ни к сети, ни к данным приложений.

## 1. Установка (один раз, примерно 10 минут)

Для каждой из двух программ:

1. SE38 → имя `ZCLAUDE_EXPORT` (потом `ZCLAUDE_IMPORT`) → **Создать**.
2. Тип: **Исполняемая программа**. Пакет: `$TMP` (локальный объект) или
   пакет проекта, если так принято у клиента.
3. Вставьте код из `src/bridge/zclaude_export.prog.abap`
   (`zclaude_import.prog.abap`) целиком, заменив шаблон.
4. **Проверить** (Ctrl+F2) → **Активировать** (Ctrl+F3).
5. По желанию задайте тексты выбора (Переход → Текстовые элементы):

| Параметр | Текст |
|---|---|
| `P_IMP` | Импорт и проверка синтаксиса |
| `P_CHK` | Только проверка, без сохранения |
| `P_UNDO` | Откатить последний импорт |
| `P_DEVC` | Пакет для новых объектов |
| `P_TRKOR` | Транспортный запрос |
| `P_OTHER` | Разрешить изменения в других пакетах |
| `S_PROG` / `S_CLAS` / `S_FUNC` / `S_TABL` | Программы / Классы / ФМ / Таблицы |
| `P_INCL` | Вместе с include-файлами |
| `P_TEXT` | Вместе с текстовыми элементами |

> Код программ пока не проверялся на живой SAP-системе. Синтаксис
> проверен статическим анализатором abaplint под SAP_BASIS 7.02, но
> сигнатуры стандартных ФМ и методов он не видит. Если при активации
> будет ошибка, пришлите её текст: исправлю.

Если SAP GUI спросит разрешение на доступ к буферу обмена, разрешите
(можно «Всегда»).

## 2. Рабочий цикл

**Я хочу изучить существующий код:**
1. Я пишу, что выгрузить (например, программу `ZSD_ORDERS` и таблицу `ZSD_LOG`).
2. Вы: `ZCLAUDE_EXPORT` → заполняете поля → F8 → результат уже в буфере.
3. Вставляете его мне в чат.

**Я отдаю код:**
1. Я присылаю пакет: блок от `*@@BUNDLE` до `*@@END`.
2. Вы копируете его (кнопкой копирования у блока кода) → `ZCLAUDE_IMPORT` → F8.
3. Отчёт уже в буфере → вставляете его мне.
4. Если есть ошибки, я присылаю исправленный пакет и повторяем шаги 2–3.
5. Когда `errors=0`, вы тестируете программу в SAP GUI и пишете результат.

## 3. Защита

- Импортируются только объекты `Z*`/`Y*`, стандарт SAP не трогается.
- Проверяются полномочия `S_DEVELOP` пользователя. Обойти их нельзя.
- Ставится блокировка редактора: объект, открытый кем-то в SE38, не будет перезаписан.
- Объект из чужого пакета не изменяется без флажка `P_OTHER`.
- Неполный пакет (без `*@@END`) отклоняется целиком.
- Перед записью старые исходники сохраняются; **`P_UNDO`** откатывает
  последний импорт. Новые объекты при откате не удаляются: программа
  подскажет, какие удалить вручную.
- Транспорты не выпускаются. Это всегда делаете вы.

## 4. Ограничения

- Импорт: только программы и include-файлы (с текстами). Классы
  пишутся локальными внутри include-файлов. Глобальные классы, ФМ и
  объекты словаря создаёте вы по моей пошаговой инструкции.
- Синтаксис проверяется до первой ошибки (так работает `SYNTAX-CHECK`).
- Экраны (dynpro) и статусы GUI не переносятся.
